# Project security and reliability audit

Date: 16 November 2026 (Africa/Lagos). Status: audit pass completed; source fixes await release and operational follow-up remains.

Scope: backend `fix/backend-production-readiness` and web `fix/project-security-audit`. Review source and installed dependencies, reproduce confirmed issues with synthetic fixtures, fix them and run unit/HTTP/database checks. Hosted checks read security metadata only. The narrow maintenance-function privilege repair below was applied to the configured Preview and Production databases after isolated verification. No hosted business rows were selected or modified, no maintenance function was invoked, and no application deployment, provider send/charge, key rotation or worker hosting activation was performed.

## Dependency advisory disposition

The full backend scan initially reported 20 affected dependency nodes (12 moderate, 8 low); the post-patch scan reports 19 (11 moderate, 8 low). These counts include parent dependency chains, not 19 independent application exploits. The production scan initially reported four nodes; after the Hono patch, the remaining production-reported adapter/Prisma chain is tied to advisory metadata whose broad range includes a publisher-patched 1.x version.

The Node adapter publisher lists 1.19.19 as patched for GHSA-rmxm-3fg6-px4f and 1.19.18 for GHSA-jpvv-r467-5p4w. The installed version is 1.19.19. Hono is locked at 4.13.19, above its fully patched 4.13.18 floor. Do not label those installed packages vulnerable solely from npm's stale cross-major range, or claim a zero-advisory scan.

Separate build/test-tool findings remain in glob/minimatch and deepmerge chains through Nest CLI, ESLint/TypeScript-ESLint and Jest/ts-jest. Compatibility work is required before changing their major versions. Do not run `npm audit fix --force`: its suggestions include downgrading Jest and TypeScript-ESLint. The API starts Nest application code; Prisma Studio/dev servers and these build/test tools are not started as public API routes. This bounds assessed exposure; it does not erase the advisories or certify the entire supply chain.

Primary references: [Hono security release](https://github.com/honojs/hono/releases/tag/v4.13.18), [Node adapter static-path advisory](https://github.com/honojs/node-server/security/advisories/GHSA-rmxm-3fg6-px4f), [Node adapter backslash advisory](https://github.com/honojs/node-server/security/advisories/GHSA-jpvv-r467-5p4w), [Supabase Data API security](https://supabase.com/docs/guides/api/securing-your-api). Scans are dated evidence, not proof of absence of unknown vulnerabilities.
